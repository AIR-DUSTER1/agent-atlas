# agentatlas 能力路线

> 更新日期：2026-10-29
> 当前基线：`0.9.0-beta.1`（开发预览）
>
> 本页描述**后续计划**，不代表功能已经交付。当前可用能力以 [README](../README.md) 和运行界面为准。

## 1. 产品方向

agentatlas 从“通用 Agent + 房产 Agent”继续演进为可组合的本地 Agent 工具集。新增能力必须继续遵守三条原则：

1. **Profile 隔离**：每个业务 Agent 使用独立工具 allowlist、审批登记和记忆 scope，不把新工具无条件塞进通用 Agent。
2. **读写分级**：检索、浏览、解析等只读能力直接执行；提交、发送、安装、修改系统状态等动作必须进入审批链。
3. **可追溯**：模型、工具、审批结果和关键副作用都进入会话回放、journal 或审计，不能只停留在 UI 文本里。

## 2. 能力清单

| 能力 | 当前状态 | 目标 | 主要边界 |
|---|---|---|---|
| Hook 生命周期扩展 | 规划中 | 在会话、回合、工具和审批节点挂接可配置动作 | 默认关闭、按事件授权、超时与递归保护 |
| 电脑操作 Agent | 已有基础工具 | 将截图 / 点击 / 输入 / 按键 / 滚动升级为独立工作流 | Windows 桌面限定、逐动作审批、实时停止 |
| 获取岗位信息 Agent | 规划中 | 聚合岗位来源，标准化、去重并按条件筛选 | 默认只读、保留来源、不绕过站点访问限制 |
| 投递简历 Agent | 规划中 | 简历匹配、材料准备、受限投递与结果记录 | 外发前强制确认、幂等、敏感信息最小化 |

### 2.1 Hook

目标是把“业务代码里硬编码的前后置动作”变成受控扩展点。首批事件计划包括：

- `session.start` / `session.end`
- `turn.start` / `turn.end`
- `tool.before` / `tool.after`
- `approval.decided`

约束：

- Hook 配置独立于技能与自定义命令；技能仍是文档注入，命令仍是提示词模板，Hook 则是会执行的动作。
- 具有副作用的 Hook 必须走审批；事件处理有超时、输出上限、并发上限与递归保护。
- Hook 失败不能静默吞掉关键副作用；审计要记录触发事件、命中规则和结果。
- Hook 不得自动获得模型密钥、用户令牌或未脱敏的会话正文。

### 2.2 电脑操作 Agent

现有 `computer_screenshot`、`computer_click`、`computer_type`、`computer_key`、`computer_scroll` 已可作为通用 Agent 工具使用。后续目标是：

- 独立 `computer` profile，减少通用 Agent 的隐式高权限面；
- 强化“截图 → 定位 → 动作 → 复核”操作闭环；
- 支持会话级紧急停止、动作节流和明确的当前窗口提示；
- 继续保持截图只读、动作类工具逐项审批的安全边界。

### 2.3 获取岗位信息 Agent

计划作为只读 Agent 独立上线：

- 通过 HTTP / CLI / MCP 插件接入岗位来源，统一为带来源、时间和原始链接的岗位结构；
- 支持关键词、城市、经验、学历、薪资、远程方式等条件筛选；
- 做重复岗位归并，但保留来源证据，不由模型补造缺失字段；
- 遵守来源站点条款和限流，不实现验证码规避或未授权抓取。

建议的工具边界：`job_search`、`job_detail`、`job_compare` 为只读；来源登录与授权由插件配置层完成。

### 2.4 投递简历 Agent

与岗位获取 Agent 分离，因为投递会改变外部世界：

- 维护候选人资料、简历版本和投递记录；
- 根据岗位描述给出匹配分析与修改建议，保留原始版本，不覆盖历史简历；
- 表单草稿可由 Agent 准备，但提交动作必须显示目标岗位、公司、简历版本和关键字段，并由用户明确批准；
- 每次投递使用幂等键，失败重试不能产生重复申请；
- 敏感资料只在本地或受保护配置中保存，不进入普通日志、错误上报或可导出的对话原文。

建议的工具边界：`resume_match`、`resume_tailor`、`application_prepare` 可自动执行；`application_submit` 必须登记审批。

## 3. 建议落地顺序

1. **Hook 基础设施**：先完成事件模型、配置校验、审批与审计，不在业务 agent 中散落回调。
2. **电脑操作收敛**：把现有工具迁入独立 profile，并补齐停止与复核闭环。
3. **岗位获取 Agent**：先接通一个可信来源，完成只读搜索、标准化、去重与来源展示。
4. **简历投递 Agent**：在岗位数据结构稳定后接入简历版本、匹配、草稿和审批提交。

每一阶段都需要同时补齐：后端类型与路由、前端状态与错误降级、审批边界、测试夹具，以及 README / Wiki 文档。

## 4. 暂不纳入

- 不默认启用 Hook，也不允许 Hook 在无审批情况下执行任意系统命令。
- 不提供绕过验证码、反爬策略或站点授权限制的岗位采集。
- 不对任何招聘平台做“批量盲投”；没有用户明确确认的投递不执行。
- 不把岗位、简历和个人资料写进全局记忆；项目级 Agent scope 仍需进一步设计。
