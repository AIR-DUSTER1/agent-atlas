# 支持策略与已知限制

## 1. 支持范围

当前支持 **Level 2 单实例自托管**：

- 一个 Web 进程；
- 一个持久化数据卷；
- TLS 反向代理；
- 文件型 journal / checkpoint / config；
- 单用户或受信任小团队共享一个访问令牌。

不支持：

- 多租户、账号体系、RBAC、按用户配额；
- 多副本共享同一数据卷；
- 数据库集群、Redis、消息队列；
- SaaS 计费、合规多租户隔离；
- Kubernetes Operator 或跨区域高可用。

这些不是“隐藏功能”，而是下一阶段架构工作。

## 2. 版本生命周期

- 生产使用语义化版本和不可变 digest。
- 补丁版本优先提供安全/稳定性修复，不引入破坏性数据格式。
- 次版本可以增加 schema migration，升级前必须备份。
- 旧版本遇到未来 schema 会 fail-closed，不支持直接降级写新数据。
- 具体支持窗口由维护者发布记录决定；生产 operator 应至少保留上一版本镜像、备份和发布证据。

## 3. 数据兼容承诺

- 配置旧版本可读取时自动迁移；
- journal / checkpoint 坏行隔离，不阻断合法行；
- 未来版本拒绝启动，提示回滚；
- 备份恢复前校验 manifest 与 SHA-256；
- 恢复失败不覆盖当前数据；
- 不承诺未备份情况下跨 major 版本降级。

## 4. 安全报告

发现漏洞时：

1. 不要在公开 issue 中粘贴 API Key、Cookie、内网地址、用户对话或可利用细节。
2. 优先使用托管平台的私密 Security Advisory / 私密报告通道。
3. 提供版本、commit/digest、复现条件、影响与最小证据；不要附带真实密钥。
4. 维护者确认后给出修复版本、缓解步骤与披露时间。

生产 operator 应将安全更新纳入既有漏洞响应流程，而不是等待“学习项目”更新。

## 5. 已知限制

- **单写者**：同一 `/data` 不能滚动部署两个进程。
- **内存态**：限流、SSE 连接、部分会话对象在进程内；重启会清空短生命周期状态。
- **外部模型**：供应商可用性、配额、协议差异不由本项目保证；熔断与超时只做降级。
- **MCP**：第三方服务死亡会降级，但无法替其修复协议或数据。
- **桌面端**：开发/个人便利壳，未完成签名、自动更新、安装包与生产崩溃收集；生产交付以 Web + Docker 为准。
- **无多用户隔离**：共享 `AUTH_TOKEN` 的用户拥有相同控制面权限。
- **备份加密边界**：`DATA_KEY` 丢失无法靠备份本身恢复。

## 6. 维护责任

生产 operator 负责：

- TLS 证书续期；
- 主机与 Docker 安全更新；
- 磁盘、备份与异机副本；
- 监控告警响应；
- 发布回滚演练；
- 真实模型配额与供应商账户安全。
